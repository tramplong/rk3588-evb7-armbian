# 03 · 全面验证报告

> **⚠ 适用范围声明（2026-11-10 实机后补充）**：本报告的 21 项全部是**镜像静态结构**校验，
> 结论"21/21 PASS"只说明镜像布局、bootloader 偏移、boot 配置正确，
> **不能覆盖运行期依赖**。实机又发现 U-Boot 的 OP-TEE 阻塞（`### ERROR ### Please RESET the board ###`），
> 见 `docs/04-实机启动诊断-OP-TEE.md`。静态校验通过 ≠ 一定能启动。

工具：`tools/armbian_image_tool.py`（纯 Python，离线解析 GPT / bootloader / ext4 / boot 配置，
不依赖 mount、losetup 或 debugfs，Windows 与 Linux 都能跑）。

复现命令：

```bash
python3 tools/armbian_image_tool.py verify \
  "G:/Downloads/硬件/Rk3588/Armbian-unofficial_26.08.0-trunk_Rk3588-evb7_noble_vendor_6.1.115_cinnamon_desktop.img.xz" \
  --deep
python3 tools/armbian_image_tool.py extract <同上> --out assets
```

原始输出存档：`docs/基础镜像校验输出.txt`。

> 检查 15 与 21 是同一个根因。修正后两项会同时变 PASS，
> 补上 extlinux 后警告也消失 → **成品应为 21/21 全通过、0 警告**。

### 附带澄清（避免误判）

- ext4 **文件系统 UUID** = `472439f3-...`（superblock `s_uuid`），
  GPT **分区 UniquePartitionGUID** = `3c60d70a-06e4-45bb-8668-6668f9e845ad`。
  两者本来就不相等；`root=UUID=` 用前者，`root=PARTUUID=` 用后者。
  初版校验脚本曾误把两相比对，已修正（校验 17）。
- U-Boot 内嵌字符串 `Force to boot from eMMC!` / `sysboot mmc 0:3 ...`
  前面紧跟 `radxa,rock-5-itx`，是 **Radxa Rock-5-ITX 的板级特判**，
  与本板 `rockchip,rk3588-evb7-lp4-v10` 无关，不是 TF 卡启动的阻碍。

## 四、已穷举但不构成阻塞的项

| 现象 | 判定 |
|---|---|
| 日志 `unknown raw ID 0 0 0` / `unrecognized JEDEC id bytes` | 板上无 SPI NOR，BootROM 探测失败的正常提示，两条日志一致 |
| `usb dr_mode not found` ×3 | U-Boot 阶段 DTS 缺 USB dr_mode，Android 也能正常起，不阻塞 |
| `Warn: can't find connect driver`（VOP） | 显示通路探测警告，HDMI1 后续正常 4K60 |
| `vsel-gpios- not found!` ×N | RK860 用 I2C 调压而非 GPIO，正常 |
| `rk_gmac ... cannot get clock mac_clk_rx/tx` | vendor gmac 走 `clock_in_out=output` + `fixed-link`，最终 `Link is Up - 1Gbps/Full` |
| `rk-pcie invalid prsnt-gpios` / `no vpcie3v3 regulator` | 未插设备的探测告警 |
| `UDC core: g1: couldn't find an available UDC` 循环 | Android USB gadget 配置残留，Armbian 下不存在 |
| `EbswSdk` / `sw_gpio` / `i2c_write failed` | 白板 OEM 服务，Armbian rootfs 不含 |
| `mmcblk1boot0` SELinux audit | Android 侧权限告警，与 Armbian 无关 |

## 五、尚未验证 / 需实机确认

1. **BootROM 层**：两份日志均为 Android 启动（未插卡），因此
   "SPL 从 eMMC 加载后回落 TF 卡 FIT" 是由日志 `Trying to boot from MMC2` 推断的强证据，
   但**尚未在插卡条件下实测**。若实机发现 BootROM 完全不扫 SD，用
   `scripts/04-android-emmc-guard.sh` 的可逆让路方案。
2. **AP6398S WiFi 固件**：基础镜像 `/lib/firmware/brcm` 内容未逐文件核对，
   首次启动若无 `wlan0`，需补 `brcmfmac4359-sdio.*` 与 nvram。
3. **主线内核路径**：本工程未做 DTS 到主线绑定的移植（工作量大），
   ophub `rk3588/6.12.y` 内核包不可直接替换，详见 `docs/02` §7。
