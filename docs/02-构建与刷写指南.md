## 0. 准备

| 项 | 要求 |
|---|---|
| 构建机 | Ubuntu 24.04（虚拟机 / WSL2 / 物理机），x86_64，root |

## 1. 路径 A —— 修复已有镜像（推荐，5 分钟，零编译）

### 1.0 无需 Linux 的极简路径（Windows 也能做）

`tools/armbian_image_tool.py patch-env` 直接对 `.img.xz` 做流式等长覆写，
只替换 `/boot/armbianEnv.txt` 所在的 4 KiB 块前 188 字节，**不需要 mount / root**：

```bash
python3 tools/armbian_image_tool.py patch-env \
  <base.img.xz> output/Armbian_rk3588-evb7_sd-boot.img.xz \
  --fdtfile rk3588-evb7-lp4-v10-linux.dtb \
  --env-file assets/boot/armbianEnv.txt
```

原理：删掉 `bootlogo=true\n`（14 B）恰好抵消新 `fdtfile` 多出的 14 B，
文件仍是 188 B → ext4 `i_size` 与 inode 校验和都不变，镜像其余 10.7 GiB 原样重压缩。
**这已经修复了唯一的启动阻断项**，产出的 `output/*.img.xz` 可直接写卡。
下面的 1.1 是"完整加强版"，会额外补 extlinux / uEnv / ophub-release / rootfs 内 bootloader。

### 1.1 完整修复（Ubuntu 24.04，root + loop）

```bash
sudo ./scripts/01-fix-sd-boot.sh \
  /path/to/Armbian-unofficial_26.08.0-trunk_Rk3588-evb7_noble_vendor_6.1.115_cinnamon_desktop.img.xz \
  ./output/Armbian_rk3588-evb7_sd-boot.img
```

可用参数：

| 参数 | 作用 |
|---|---|
| `--compress` | 额外生成 `.img.xz`（约 1.9 GiB，便于分发） |
| `--skip-verify` | 跳过最后 21 项校验（不推荐） |

脚本 7 个阶段的预期输出：

```
[1/7] 展开基础镜像 -> work/rk3588-evb7-build.img     （10.7 GiB）
[2/7] 校验输入镜像的启动结构                        （快速模式，秒级）
[3/7] 挂载 rootfs ... ext4 UUID = 472439f3-...
[4/7] 修正 /boot 启动配置                            ★ 关键修复
[5/7] 按 ophub Rockchip 规范重写 bootloader          sector 64 / 16384
[6/7] 输出成品 + sha256
[7/7] 成品全量校验（21 项）                          应为 21 PASS / 0 FAIL / 0 WARN
```

### 到底改了什么

| # | 改动 | 原因 |
|---|---|---|
| 1 | `fdtfile` → `rockchip/rk3588-evb7-lp4-v10-linux.dtb` | 原值指向不存在的 `rk3588-evb7.dtb`，`boot.scr` 的 `load ... dtb/${fdtfile}` 必然失败，这是启动不起来的根因 |
| 2 | 新增软链 `dtb/rockchip/rk3588-evb7.dtb` → `rk3588-evb7-lp4-v10-linux.dtb` | 即便某个 boot.scr / 环境仍用旧名也能解析 |
| 3 | `rootdev` 对齐 ext4 `s_uuid` | 防止 TF/eMMC 同时存在时设备号漂移；基础镜像本来就是对的，脚本做二次确认 |
| 4 | `bootlogo=false`、`earlycon=off` | 减少串口噪音，便于排障；需要 earlycon 时改回 `on` |
| 5 | 新增 `/boot/extlinux/extlinux.conf` + `mmc0_extlinux/` + `mmc1_extlinux/` | 对齐 ophub 对 RK3588 出厂 U-Boot 的兼容做法（QuarkPi-CA2 同款），给 distro boot 多三条命中路径 |
| 6 | 新增 `/boot/uEnv.txt` | ophub 风格兜底 |
| 7 | `/etc/ophub-release` | 板级标识，便于后续 `armbian-*` 工具识别 |
| 8 | `/usr/lib/u-boot/{idbloader.img,u-boot.itb}` | 与板子 DDR 参数完全匹配的 bootloader，供日后写 eMMC / 更新用 |
| 9 | 重写镜像 sector 64 / 16384 | 与 ophub `rebuild` 的 `dd bs=512 seek=64 / seek=16384` 一致 |

> **不改的东西**：内核、initrd、modules、rootfs 内容、GPT 分区表、原厂 Android、eMMC。

## 4. 故障排查决策树

```
通电无任何串口输出
└─ 串口参数错？确认 1500000 8N1、接的是 UART2(0xfeb50000)、TX/RX 对调
└─ 换 TF 卡（UHS SDR104 对卡敏感），或先用 USB 读卡器确认卡能读

只看到 Android 启动（"Trying to boot from MMC1" 直接走了）
├─ 先确认 TF 卡 sector 64 有 RKNS、sector 16384 有 d0 0d fe ed
│   sudo dd if=/dev/sdX bs=512 skip=64     count=1 | xxd | head
│   sudo dd if=/dev/sdX bs=512 skip=16384  count=1 | xxd | head
├─ 确认卡插在板载卡槽（非 USB），且卡座检测脚 GPIO0_A4 正常
└─ 仍不行 → 执行 scripts/04-android-emmc-guard.sh 的 backup + disable
            （可逆，先备份到 TF 卡/U 盘并复制到 PC）

SPL 起来了但卡在 "Trying fit image" / 校验失败
└─ eMMC 的 SPL 与卡上 u-boot.itb 代次不匹配 → 用 assets/bootloader 的
   那一对（脚本已自动写入）；或改用 05-build-uboot.sh 重建

U-Boot 起来但停在 "Scanning ..." 找不到 boot.scr
└─ 检查 boot_targets（本板应为 usb0 mmc1 mmc0 ...）
└─ 手动：U-Boot> mmc dev 1; ls mmc 1:1 /boot
└─ 手动：U-Boot> load mmc 1:1 ${scriptaddr} /boot/boot.scr; source ${scriptaddr}

出现 "load ... dtb/rockchip/xxx.dtb" 失败
└─ fdtfile 又指错了 → 见 docs/03，改成 rk3588-evb7-lp4-v10-linux.dtb

内核起来了但 "Waiting for root device" / VFS 无法挂载
├─ rootdev 应为 ext4 文件系统 UUID（不是 GPT PARTUUID、不是 /dev/mmcblk0p1）
├─ U-Boot> 可用 setenv rootdev 'root=PARTUUID=3c60d70a-...' 临时试
└─ 检查 bootargs 是否带了 rootwait

HDMI 黑屏但有串口
├─ 确认接的是 HDMI1（fdea0000），HDMI0(fde80000) 在原厂日志里是 disconnected
└─ 内核命令行加 drm.debug=0x1f 或 loglevel=8 看 VOP 绑定

网卡不工作
└─ 本板是 fixed-link 1000/full + rgmii-rxid，不需要 PHY 协商；
   若 vendor 内核里 rk_gmac 未编译，说明 DTB/内核代次不匹配
```

## 5. 保护 / 恢复原厂 Android

**默认完全不需要动 eMMC。** 只有确认 BootROM 抢不过 eMMC 时才用，
且脚本强制先备份、校验、二次确认。

在板子上（Armbian 已启动，或 Android `adb shell` 里）：

```bash
# 1) 备份到 TF 卡或 U 盘（不要放 eMMC），再复制到 PC
./04-android-emmc-guard.sh status
./04-android-emmc-guard.sh backup  /media/usb/emmc-backup

# 2) 临时让路（只清 sector 64..32767 的 bootloader 区，GPT 与 21 个分区不动）
./04-android-emmc-guard.sh disable /media/usb/emmc-backup

# 3) 想回 Android 时
./04-android-emmc-guard.sh restore /media/usb/emmc-backup
# 拔掉 TF 卡重启
```

清掉的 16 MiB 里包含：
- sector 64 起 `RKNS` idbloader（DDR + SPL）
- sector 16384 起 `u-boot.itb` FIT（ATF/BL31 + U-Boot + OP-TEE）

保留不动：LBA 0 保护 MBR、LBA 1 GPT 头、LBA 2–33 分区项、
`mmcblk1p1..p21` 全部 Android 分区、`mmcblk1boot0/boot1`、RPMB。

## 6. 可选：关掉白板专用外设，消除 i2c 报错

反编译 DTS 里的白板专用节点（Linux 下没有对应驱动）：

| 节点 | 位置 | 作用 |
|---|---|---|
| `icm_acc@68` / `icm_gyro@68` (`compatible = "icm42607_acc"/"icm42607_gyro"`) | `i2c@feac0000` (i2c4) | 加速度计/陀螺仪 |
| `nxpnfc@28` | `i2c@fead0000` (i2c5) | NFC |
| `ebsw_pwm` (`compatible = "ebsw, ebsw-pwm"`) | 根节点 | 白板背光/OEM |
| `rkcif*` / `rkisp*` / `csi2-dphy*` | 多处 | 摄像头链路 |

做法：写一个 DT overlay，用 `delete-node` 或 `status = "disabled"` 关掉，
放到 `/boot/overlay-user/`，在 `armbianEnv.txt` 里加 `user_overlays=evb7-no-whiteboard`，
`boot.scr` 会自动 `fdt apply`。示例：

```dts
/dts-v1/;
/plugin/;
/ {
    fragment@0 { target-path = "/i2c@feac0000/icm_acc@68";
        __overlay__ { status = "disabled"; }; };
    fragment@1 { target-path = "/i2c@feac0000/icm_gyro@68";
        __overlay__ { status = "disabled"; }; };
    fragment@2 { target-path = "/i2c@fead0000/nxpnfc@28";
        __overlay__ { status = "disabled"; }; };
    fragment@3 { target-path = "/ebsw_pwm";
        __overlay__ { status = "disabled"; }; };
};
```

```bash
dtc -I dts -O dtb -@ -o /boot/overlay-user/evb7-no-whiteboard.dtbo evb7-no-whiteboard.dts
echo 'user_overlays=evb7-no-whiteboard' >> /boot/armbianEnv.txt
```

> 这一步**不影响能否启动**，只是让 dmesg 干净。排在首次启动成功之后做。

## 7. 路径 B —— 接入 ophub rebuild 体系

```bash
./scripts/02-ophub-integration.sh --clone
sudo ./scripts/02-ophub-integration.sh --kernel-tarballs \
    ./output/Armbian_rk3588-evb7_sd-boot.img
sudo ./scripts/02-ophub-integration.sh --run
```

脚本自动完成：

| ophub 路径 | 内容 |
|---|---|
| `.../common-files/etc/model_database.conf` | 追加 `board/model_database.conf.entry` 的 15 列条目 |
| `.../u-boot/rockchip/rk3588-evb7/` | `idbloader.img` / `u-boot.itb` / 板级 DTB |
| `.../different-files/rk3588-evb7/bootfs/` | `armbianEnv.txt` / `uEnv.txt` / `extlinux/extlinux.conf.bak` |
| `.../different-files/rk3588-evb7/rootfs/etc/` | `ophub-release` |
| `.../kernel/rk3588/<ver>/` | `boot-*.tar.gz` / `dtb-rockchip-*.tar.gz` / `modules-*.tar.gz` / `header-*.tar.gz` |

ophub `rebuild` 对 Rockchip 的关键约定（已核对源码）：

```bash
skip_mb="16"; partition_table_type="gpt"; bootfs_type="ext4"
dd if=idbloader.img of=$loop bs=512 seek=64     conv=fsync,notrunc
dd if=u-boot.itb    of=$loop bs=512 seek=16384  conv=fsync,notrunc
# 三文件齐备时才额外写 seek=24576 的 trust.img（本板 TRUST_IMG=NA）
parted mkpart primary ext4 16MiB $((16+boot_mb-1))MiB
parted mkpart primary ext4 $((16+boot_mb))MiB 100%
ln -sf uInitrd-<ver> /boot/uInitrd ; ln -sf vmlinuz-<ver> /boot/Image
ln -sf dtb /boot/dtb-<ver>
```

### ⚠ 内核绑定不兼容（必读）

| | ophub `rk3588` 内核包 | 本板 vendor 6.1.115 BSP |
|---|---|---|
| DTB 命名 | `rk3588-rock-5b.dtb` 等主线风格 | `rk3588-evb7-lp4-v10-linux.dtb` |
| PMIC 绑定 | 主线 `rk806` (regulator) | `rockchip,rk806` @ spi2 + RK8602/8603 |
| GMAC | 主线 `snps,dwmac` + real PHY MDIO | `rockchip,rk3588-gmac` + `fixed-link 1000/full` |
| SDMMC | 主线 `rockchip,rk3588-dw-mshc` + `sdhci` 变体 | vendor `dw-mshc` + `vccio_sd_s0` |
| WiFi | 主线 DT 节点 | `wlan-platdata` / `ap6398s` |

**直接拿 ophub 现成的 `rk3588/6.12.y` 内核 rebuild，本板会丢 PMIC / 网口 / SD 驱动。**
所以必须走 `--kernel-tarballs` 用你自己的 vendor 内核打包。
若 fork 的 ophub 版本对 `-k` 版本白名单有变化，按 `rebuild` 里
`kernel_boot / kernel_dtb / kernel_modules / kernel_header` 四个变量核对目录与文件名。

若最终目标是主线 6.12+，需要把 `rk3588-evb7.dts` 从 vendor 绑定移植到主线绑定，
这属于独立任务，本工程不含。

## 8. 路径 C —— armbian/build 从源头修

你已有 `rk3588-evb7.csc` 编译环境时，只需按
`board/rk3588-evb7.csc` 的片段把 `BOOT_FDT_FILE` 改成
`rockchip/rk3588-evb7-lp4-v10-linux.dtb`，然后：

```bash
./compile.sh build BOARD=rk3588-evb7 BRANCH=vendor RELEASE=noble \
    BUILD_DESKTOP=yes BUILD_MINIMAL=no KERNEL_CONFIGURE=no
```

产物天然带正确的 `fdtfile`，无需再跑路径 A。
`board/rk3588-evb7.csc` 里同时标注了 `KERNEL_TARGET=vendor`、`CONSOLE=ttyS2,1500000`
等必须核对的字段。

## 11. 常见问题

**Q：拔卡还能回 Android 吗？**
能。路径 A 完全不写 eMMC。只有执行过 `04-android-emmc-guard.sh disable` 才需要 `restore`。

**Q：能不能把 Armbian 装进 eMMC？**
可以但不建议直接做：先用 `armbian-ddbr` 类工具**全盘备份 256 GiB 原厂 Android**
（含 21 个分区与 GPT），再 `dd if=armbian.img of=/dev/mmcblk1`。
注意 ophub 在 Rockchip 平台会主动删除 `usr/sbin/armbian-install`，不要指望它。
本工程默认不提供该操作。

**Q：为什么不用 ophub 的 `armbian-install -m yes`？**
那是给 Amlogic/Allwinner 用的；README 明确 Rockchip 走第 8 章流程，
且本板 DTB 与 ophub 主线内核不兼容。

**Q：镜像 10 GiB，TF 卡只有 16 GB 够吗？**
够（rootfs 分区 10203 MiB）。建议 32 GB 以上，首次启动后 resize2fs 用满。

**Q：串口波特率到底是多少？**
1500000（Android 日志 `earlycon=uart8250,mmio32,0xfeb50000`，
Armbian `console=ttyS2,1500000`）。115200 会看到乱码。
